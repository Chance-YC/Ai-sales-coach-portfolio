## 📌 这是什么

这是一个**完整的产品经理作品集项目**：以「B2B 销售团队的 AI 赋能」为命题，覆盖从用户调研、需求分析、产品路线规划、用户流程设计、PRD 撰写，到面向研发的内部技术方案的全流程，并附带一个**可直接打开交互的原型 Demo**。

> ⚠️ **作品集声明**：本项目为个人作品集性质的模拟产品案例。调研方法、分析框架、文档结构均按真实产品流程构建，文中访谈样本与数据为案例设定，用于完整展示产品工作方法。

## 🎯 为什么做这个产品

**三个真实存在的行业痛点：**

1. **新人成长慢**：B2B 销售新人平均需要 3 个月以上才能独立谈单，Top Sales 的经验依赖口口相传，无法沉淀；
2. **异议处理没章法**：客户异议（"太贵了""再考虑"）是丢单的首要原因，但多数销售靠临场发挥；
3. **跟进效率低**：销售日均花费 1 小时以上写跟进邮件、翻话术资料，时间没有花在客户身上。

**产品定位**：轻量级 AI 销售助手，切入「场景化话术生成 + 异议应对 + 跟进邮件」三个高频刚需场景，让每个销售在见客户前 5 分钟内拿到一份可用的作战方案。

## 🎮 原型 Demo

`demo/index.html` 是一个**零依赖、单文件可交互原型**，本地双击即可打开：

- **场景话术生成**：选择行业 / 客户角色 / 沟通阶段 / 本次目标 → 生成完整作战方案（开场白、提问框架、价值主张、下一步行动）
- **异议应对教练**：五步应对法（认同 → 探究 → 重构 → 证据 → 推进）
- **跟进邮件助手**：输入沟通要点 → 生成结构化跟进邮件

> Demo 内置本地规则引擎模拟生成效果。点击顶部「🔌 本地演示 · 点击切换」可启用真实 LLM（DeepSeek），首次需要输入自己的 API key（仅保存在浏览器本地，不上传服务器）。
>
> 接口设计已在[技术方案 §5](./docs/06-技术方案与内部设计.md#5-话术生成引擎设计)中说明。

## 🚀 如何运行

```bash

cd demo && python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

## 🌐 部署到 GitHub Pages（让简历里的链接直接可访问）

1. 在 GitHub 创建仓库（建议命名 `SalesMate` 或 `ai-sales-assistant-portfolio`）
2. 推送代码：

```bash
git init
git add .
git commit -m "feat: SalesMate AI 销售助手产品作品集 V1.0"
git branch -M main
git remote add origin https://github.com/<你的用户名>/SalesMate.git
git push -u origin main
```

3. 仓库 **Settings → Pages → Source 选择 `main` 分支 / root**，保存
4. 约 1 分钟后访问 `https://<你的用户名>.github.io/SalesMate/demo/` 即可在线演示
